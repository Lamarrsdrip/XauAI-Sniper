# XauCloud agent-readiness release checks — 2026-11-02

These changes share the production-gated XauCloud purchase/UX PR. Neither a successful build nor a merge means production has been deployed.

## Implemented

- Both robots files contain \`Content-Signal: search=yes, ai-train=no\`. This is a publisher preference, not an enforceable guarantee of crawler compliance.
- The sitemap is generated at build time using the latest relevant Git content modification dates (with a source-verified fallback for shallow checkouts). Do not use the current wall clock as a fake page-edit time.
- Node's previous universal HTTP 200 SPA fallback is restricted to known application routes; unknown paths return an HTML document with HTTP 404, one h1 and noindex. Campaign slugs must correspond to a **published** landing page in MongoDB.
- Public SSR HTML fallback has one actual h1, route-aware canonical/title, and real HTML navigation. React replaces the fallback on hydration. Private pages still require normal authentication.
- Organization and SoftwareApplication JSON-LD is generated by the production Node server. The verified MQL5 product listing is the product external identity; the creator's X profile is identified as a creator, not incorrectly as a corporate X account. There is **no** hardcoded obsolete NGN product price in structured data.
- Contact email and telephone derive from existing administrator support settings. A PostalAddress is emitted only when the administrator sets street, city and country; **never invent a postal address**. The admin form has fields for validated public postal information. Public GET /api/public/contact serves only this validated public subset.
- About, Contact, Terms, Privacy, Risk pages are real React routes linked in the shared footer and in the no-JavaScript HTML fallback.
- Both build/public \`/llms.txt\` assets contain a title, summary and links. \`/index.md\` is a real Markdown page. The Node root and published public pages also negotiate \`Accept: text/markdown\` and set an RFC 8288 Link header. All responses should have the correct Content-Type.
- Browser WebMCP is registered **only where the experimental API exists**, with one read-only public-navigation tool and no payment/trading/account actions.
- The MCP server card is served as JSON at \`/.well-known/mcp/server-card.json\` and describes a real, read-only Streamable HTTP JSON-RPC endpoint at \`/mcp\` with initialization, ping, tools/list and tools/call. No fake backend functionality is advertised. Only anonymous public information is available.

## Post-deployment live smoke checks

Use GET and HEAD where appropriate, and check the **actual HTTP status**, Content-Type and contents. These commands do not submit any transaction.

\`\`\`sh
curl -si https://xaucloud.io/robots.txt
curl -si https://xaucloud.io/sitemap.xml
curl -si https://xaucloud.io/llms.txt
curl -si https://xaucloud.io/index.md
curl -si https://xaucloud.io/.well-known/mcp/server-card.json
curl -si https://xaucloud.io/about
curl -si https://xaucloud.io/contact
curl -si https://xaucloud.io/terms
curl -si https://xaucloud.io/absolutely-not-a-real-page-404
curl -si -H 'Accept: text/markdown' https://xaucloud.io/
curl -si -X POST https://xaucloud.io/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"audit","version":"1"}}}'
\`\`\`

Acceptance: a bogus page returns 404; valid pages return 200 and exactly one meaningful h1 in the HTML response; llms.txt returns text/plain not the SPA; \`index.md\` and markdown negotiation return text/markdown; the card returns JSON and its endpoint actually initializes; the public identity contains only configured values; the sitemap has per-URL lastmod.
