# XauCloud local AI (Windows VPS)

This deployment is intentionally loopback-only and zero-credit by default.
Customer EAs reach it through the authenticated `https://xauaisniper.com`
relay; the VPS worker makes outbound HTTPS requests only.

- Runtime: pinned native `llama.cpp` b10229 with the benchmark-selected model
  declared in `start_runtime.cmd`.
- Runtime endpoint: `http://127.0.0.1:11434`.
- Gateway endpoint: `http://127.0.0.1:8765/api/local-ai/*`.
- Runtime limits: 2 CPU threads, 2,048-token context, one slot, low process priority.
- Gateway limits: one non-queued inference, 40-second timeout, 70% CPU ceiling,
  2 GB minimum free RAM, and deterministic fallback.
- Local AI confidence below 70 is ignored for trading and the deterministic
  pure-M10 engine decides.
- Paid/cloud AI is not called by this service. An optional Emergent fallback
  belongs behind a separate explicit opt-in gate and is disabled by default.
- The cache is `C:\XauCloudLocalAI\cache\decisions.sqlite3` (SQLite WAL).
- Model/prompt cache keys use the strict `xaucloud-local-ai-v4` contract.
- Strategy Tester uses exact offline snapshot/decision pairs generated by
  `python -m local_ai.build_replay_cache`; it never attempts WebRequest.
- Scheduled tasks are `XauCloudLocalAI_Runtime` and
  `XauCloudLocalAI_Gateway`, plus `XauCloudLocalAI_RemoteWorker`; all run as
  `SYSTEM` at boot without login.
- The signing private key lives only in
  `C:\XauCloudLocalAI\secrets\worker_private_key.pem`; the backend contains
  only its public key. The private key must never be embedded in a customer
  EA or committed to Git. Each request is signed with a timestamp and unique
  nonce, and replayed signatures are rejected.
- The task commands execute their child process directly (no detached
  `start /wait` process), so Task Scheduler stop/restart owns the real process
  lifecycle. The gateway sets its own Windows priority to below-normal.

No firewall rule is created. Both listeners must resolve to `127.0.0.1` only.
