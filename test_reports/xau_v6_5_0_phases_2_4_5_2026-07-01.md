# XAU AI Sniper v6.5.0 — Phases 2 + 4 + 5 (bundled per explicit owner request)

Date: 2026-07-01

The staged release plan called for v6.4.26 (Phase 2), v6.5.0 (Phase 4), and
v6.5.1 (Phase 5) as three separate releases. After flagging that Phase 3
cannot be compressed (it requires 2+ weeks of real live-trading data that
doesn't exist yet) and Phase 4 is a genuine architecture change, the owner
explicitly confirmed bundling everything possible right now into one
version. This release is that bundle. Phase 3 is NOT included — there is no
way to fake the elapsed time it requires.

## Why this release does not add a fear layer or weaken profit growth

Every change either fixes a proven defect (tautological condition, dead
code, an unfair penalty on a missing AI answer), consolidates duplicate
logic without changing what evidence it accepts, or hardens
non-trading infrastructure (backend security, dead code, docs). None of it:
- adds a new protective/veto layer,
- makes any entry stricter,
- reduces any lot size,
- reintroduces B-grade blocking,
- reduces trade frequency.

The Growth Guard fix (#5) specifically *removes* a hidden restriction (a
structure-blind stop tighter than the real SL). The AI fallback fix (#8)
specifically *removes* an unwarranted lot-halving penalty. The Exit Arbiter
(Phase 4) adds a new capability (per-ticket BOS/HTF flip detection) that
only makes it *easier* to prove a hold is justified, not harder.

## Phase 2 — Growth Guard/June-mode reconciliation, honest AI, remaining basket gates

### Bug #5 — GROWTH_HARD_LOSS_EXIT tautology / June-mode mismatch (CRITICAL)
`maxTradeLossUSD <= equity * 0.015` compared the cap against the exact
percentage its own default (`InpGrowthMaxTradeLossEquityPct = 1.50`) equals,
making the clause always true and the whole OR-condition unconditional.
Combined with `JUNE_16_19_BALANCE_MODE` sizing lots off balance/grade (not
SL distance), this created a hidden ~$45 structure-blind stop on trades
whose real SL risk could be $489+. Live evidence: a +$77.91 winner survived
this cap by about $2 (`worstFloating=-$43.68` vs a `$45.70` cap) before
running to profit.

**Fix (`XAU_GrowthGuardManagePosition`):**
- Compared the tautological clause against `equity * 0.008` instead of
  `equity * 0.015` — now only self-triggers on an unusually tight configured
  cap, restoring the intended requirement for real evidence (thesis failing
  or inside the early-adverse window) otherwise.
- New `InpGrowthJuneModeCapSLMultiple` (default `1.0`): in June mode, raises
  the cap to at least the trade's real SL-distance risk
  (`RiskPerLotForDistance(slDist) * lotsOpen`), so the broker SL — not a
  hidden tighter EA-side cap — is the operative stop, matching the intent of
  the original June-mode restore.

### Bug #8 — AI fallback confidence=50 masquerading as judgment (HIGH)
Backend returned `confidence=50` both for a genuine dual-AI SKIP verdict AND
for a provider-unavailable/error fallback, making a missing opinion
indistinguishable from a real (if modest) one. Live evidence: 88 hard entry
vetoes on 2026-06-30 fired off this exact constant.

**Fix:**
- `backend/server.py`: the `else` branch of `_ask_dual_entry_ai` (or
  equivalent) now returns `confidence=50` only when both providers actually
  answered and both said SKIP; `confidence=0` when at least one is
  unavailable/errored. The top-level exception handler also returns
  `confidence=0`, not 50.
- EA (`ProcessAIDirectorVerdict`-equivalent SKIP branch): the B-grade
  lot-halving (`sizeMulti x0.50`) now only applies when `lastAIConfidence >
  0` (a real answer). `confidence=0` now logs `NO-AI-ANSWER` and proceeds at
  full size — no penalty for an AI that never weighed in. The existing
  `BLOCK LOW-CONF` path already required `lastAIConfidence > 0`, so it now
  correctly stops firing on fallback data too.

### Bug #6 — remaining mechanical basket exits (MEDIUM-HIGH)
`SECOND_CHANCE_PROFIT_EXIT` had no gate call at all; both `CYCLE_DECAY_EXIT`
branches called the gate but without `isGivebackTrigger=true`, so a
still-profitable basket auto-allowed the close regardless of evidence.

**Fix:** all three now route through `XAU_GateEarlyLossClose(...,
isGivebackTrigger=true)`, requiring either a confirmed structure break or
that the basket already exhausted its cycle budget — a still-recovering,
non-exhausted, non-reversed basket now holds instead of banking a modest
recovery mechanically.

## Phase 4 — Unified Exit Arbiter (scoped to the close-decision layer)

The audit found four different, sometimes-disagreeing "structure broken"
definitions (M5 swing break, SMC H1 BOS, TTM entry-vs-current flip, ad hoc
EMA/RSI/momentum combos computed inline per site) and noted per-ticket close
gates never used the BOS/HTF flip check the basket-level gate got in
v6.4.25 — the exact gap that let a trade entered against a standing BOS
still lose the benefit of the doubt.

**Fix:** new `XAU_ReversalConfirmed(ticket, isBuy, structureConfirmedBroken,
emaAgainst, rsiAgainst, momentumScore, trendAligned)` — the union of what
`SMART_EXIT_GIVEBACK` and `SMART_EXIT_TREND` already independently accepted,
plus a per-ticket BOS/HTF flip check using TTM's entry snapshot
(`TTM_FindActiveSlot`, read-only). Both call sites now route through it
instead of computing their own inline combination.

**Scope decision:** this unifies the CLOSE decision (the actual duplicate/
contradiction problem — competing, unproven full-close triggers), not the
independent SL-trailing math of AMPL, the EV engine, A+ Shield, or
Chandelier trailing. Those remain separate, reversible ratchets; multiple
systems tightening a stop is not the same failure mode as multiple systems
independently deciding to fully close a position, and rewriting all of
their internal math in the same pass as everything else in this release
would be exactly the kind of untested mega-change the staged-release
instruction was meant to prevent.

## Phase 5 — Platform cleanup and security hardening

- **Admin password (bug #9):** removed the hardcoded `"Admin@2026!"`
  fallback (was sitting in plaintext on a public repo — admin access grants
  master-EA download and payment/SMTP settings). Generates and logs a
  random one-time password if `ADMIN_PASSWORD` isn't set.
- **JWT_SECRET (bug #9):** now persists to `backend/.jwt_secret`
  (gitignored) instead of regenerating on every process restart, which
  invalidated every session and would have made encrypted data
  unrecoverable after a restart.
- **Admin cookie:** `secure=False` -> `secure=True` by default
  (`COOKIE_SECURE=false` env var available for local HTTP dev).
- **CORS:** `allow_credentials` no longer `True` alongside a wildcard `*`
  origin default.
- **Dead code removed:** `PinManagerSection.jsx` (confirmed unmounted, zero
  references), `backend_test.py` (stale standalone "Iteration 9" script,
  superseded by `backend/tests/`).
- **README:** no longer hardcodes a version number (was stale at v6.4.21
  while backend served v6.4.24) — documents the live `/api/download/info`
  source of truth instead.
- **Two previously-missed site files fixed:** `CloudLanding.jsx` and
  `CloudDashboard.jsx` had been showing `v6.4.21` since v6.4.22 — missed in
  every version-bump distribution step since. Now `v6.5.0` and added to the
  standard distribution list.
- **Regression suite repaired:** 71 of ~119 tests were failing before this
  release, entirely from hardcoded references to EA filenames/version
  strings from superseded releases (audit bug #11 — the exact test-rot
  pattern). Repointed the working tests at the current file, removed
  assertions that were genuinely one-release-only (each superseded by that
  release's own dedicated identity test), and made the generic
  release-label tests derive the current version from the EA's own
  `XAUAI_EA_VERSION` macro instead of a hardcoded literal — this class of
  staleness cannot recur on future version bumps without the test itself
  catching it. Suite is now 126/126 (118 existing + 8 new for this release).
