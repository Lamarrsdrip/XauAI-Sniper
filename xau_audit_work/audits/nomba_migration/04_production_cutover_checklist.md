# Nomba Payment Migration — Production Cutover Checklist

Nothing in this checklist has been done automatically — every item here
requires the owner's own action, credentials, or a decision only they
can make. This session built and verified the code; it did not (and
could not) flip any of these switches.

1. **Nomba business/KYC approval confirmed** — owner's own action on
   Nomba's dashboard, outside this codebase.
2. **Production API access enabled** on the Nomba account.
3. **Correct production `accountId`** — enter via Admin Dashboard →
   Settings → Payments → Nomba → Production credentials.
4. **Production webhook URL confirmed** — the admin config page displays
   the exact URL to copy: `{PUBLIC_SITE_URL}/api/webhook/nomba`. Paste
   this into Nomba's own dashboard (Developer → Webhook Setup), live
   webhook URL field.
5. **HTTPS confirmed** — `PUBLIC_SITE_URL` must be `https://`, already
   the case (`https://xauaisniper.com`).
6. **Production webhook signature key confirmed** — generated by Nomba
   when the live webhook is set up on their dashboard; enter the same
   value into the Admin Dashboard's Production → Webhook Signature Key
   field.
7. **Successful production credential authentication confirmed** — use
   the admin dashboard's "Test Connection" button after entering
   production credentials; it performs a real OAuth token issuance
   (never a charge) and records pass/fail with a timestamp.
8. **Live product price confirmed** — Settings → Pricing → PIN price
   (Naira), shared by both Nomba and any still-resolving Paystack
   transaction.
9. **Allowed payment methods confirmed** — Admin Dashboard checkboxes;
   defaults to card/transfer/ussd/qr, matching what Nomba's own
   Nigerian-account checkout page supports per
   `audits/nomba_migration/02_nomba_api_reference.md` — do not enable a
   method not actually active on the Nomba account.
10. **No Paystack button remains** — confirmed in this session:
    `PurchaseSection.jsx` only calls `/purchase/initialize`, which is
    Nomba-exclusive; no Paystack script/SDK was ever loaded client-side
    to begin with (verified in the Phase 1 audit).
11. **Old Paystack records remain intact** — confirmed: no delete/update
    touches historical `payment_transactions`/`pin_licenses` rows beyond
    the purely additive `provider` backfill (migration 0002, dry-run
    verified against a seeded test database in this session).
12. **Database backup confirmed** — run migration 0002 in dry-run mode
    first (default, no `--confirm` flag) against the real production
    `MONGO_URL`/`DB_NAME` and review its output; it also writes its own
    timestamped backup to `backend/migrations/backups/` before any write,
    verified non-empty before proceeding, same pattern as
    `0001_delete_copy_trading.py`. A full separate database snapshot
    through your hosting provider's own backup mechanism, taken
    immediately before running migration 0002 with `--confirm`, is the
    owner's own action and is recommended in addition to the migration's
    built-in backup.
13. **Rollback plan** — to fall back: (a) set
    `payment_nomba_config.enabled = false` via the admin dashboard
    (instant, no deploy needed) — `/purchase/initialize` will then 503
    rather than silently doing something wrong; (b) if a full code
    rollback is needed, this entire migration lives on
    `feature/nomba-payment-gateway` and was never merged to `main`, so
    reverting is simply not merging / reverting the merge commit; (c)
    the database migration is additive-only (a `provider` field), so no
    schema rollback is required even if the code is rolled back.
14. **Final configuration screen** — the Admin Dashboard's
    Settings → Payments → Nomba section itself is the "final
    configuration screen": environment selector, masked credential
    previews, last-validation status/timestamp, callback/webhook URLs,
    and Test Connection all in one place for the owner to review before
    flipping "Enable Nomba Payments" and switching environment to
    Production.

## Explicitly not done by this session, per the spec's own instruction

- No real credentials were entered anywhere in this session.
- No real charge was made or attempted.
- No production cutover was performed — `environment` defaults to
  `"sandbox"` and `enabled` defaults to `false` in the new
  `payment_nomba_config` collection; both require explicit owner action
  through the admin dashboard.
